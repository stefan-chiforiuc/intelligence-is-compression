Talking points:
  * A flat line means the code was already optimal on the first run (AOT).
  * A falling line means the runtime is COMPILING WHILE YOUR USERS WAIT (JIT).
  * A spike mid-run in Node or Java is usually a deoptimisation.
  * Compare `java` with `java -Xint` (--xint) to see what the JIT is worth:
    that gap is roughly the value the JVM adds over pure interpretation.
